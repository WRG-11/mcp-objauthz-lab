# Challenge S10 — The Header the Gateway Trusts

**Difficulty:** Intermediate
**Class:** CWE-639 / CWE-290 — forwarded-header-as-scope (transport surface)
**Tool under test:** `note_get_scoped`

## Setup

S10 lives on the **HTTP transport** — it is the one scenario that does not
manifest over stdio, because stdio has no request headers. Run the HTTP
server instead of `src/server.js`:

```bash
npm install

# Only S10 is left vulnerable; the rest default to "vuln" when unset.
LAB_S10=vuln LAB_S1=fixed LAB_S2=fixed LAB_S3=fixed LAB_S4=fixed LAB_S5=fixed LAB_S6=fixed LAB_S7=fixed LAB_S8=fixed LAB_S9=fixed LAB_S11=fixed LAB_S12=fixed LAB_S13=fixed node src/http-server.js
# → [mcp-objauthz-lab:http] up on :3010  S10=vuln
```

## Your mission

You are **Alice** (`alice-token`, org *Acme*). The server sits behind an API
gateway, and its `note_get_scoped` tool lists "the caller's notes." Its
description says it *"honors an X-Org-Id routing header set by the API
gateway."*

You are not a member of *Globex*. You have no Globex token, no membership —
only `alice-token`. But you speak to the server directly, so **you** decide
what headers the request carries, not the gateway.

Connect an MCP client to `http://127.0.0.1:3010/mcp` and call
`note_get_scoped` with `{ "token": "alice-token" }`. Then send it again with
one extra HTTP header and read notes that are not yours.

## What to look for

- Which value does the tool use to decide *whose* notes to return — something
  the server derived from your token, or something you sent?
- Over stdio there are no headers, so the same tool falls back to the session.
  Why does moving to HTTP open the hole?
- The exploit is a single request header. No token theft, no membership, no
  guessing note ids.

## Success criterion

The exploit succeeds when a request you authenticate as **Alice** returns a
note whose `orgId` is `org_globex` (e.g. `n_globex_1`, "Globex roadmap").

## Verify the fix

Restart with `LAB_S10=fixed node src/http-server.js` and repeat: the same
spoofed header is now ignored, and you only ever see *Acme* notes.

See [solutions/s10.md](../solutions/s10.md) for the walkthrough and the fix.
