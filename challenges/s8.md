# Challenge S8 — The Path You Wrote

**Difficulty:** Intermediate
**Class:** CWE-639 — resource-URI-as-scope (resources/read surface)
**Resource under test:** `note://{token}/{orgId}/{noteId}`

## Setup

```bash
npm install

# Only S8 is left vulnerable; the rest default to "vuln" when unset.
LAB_S8=vuln LAB_S1=fixed LAB_S2=fixed LAB_S3=fixed LAB_S4=fixed LAB_S5=fixed LAB_S6=fixed LAB_S7=fixed LAB_S9=fixed LAB_S10=fixed LAB_S11=fixed node src/server.js
```

## Your mission

You are **Alice** (`alice-token`, org *Acme*). Every scenario so far has been a
tool (`tools/call`). This one lives on a different MCP primitive: the lab
publishes a resource template, `note://{token}/{orgId}/{noteId}`, that lets a
client read a single note through `resources/read` instead of a tool call.

You want to read Globex's note `n_globex_1`. You are not a member of *Globex* —
no Globex token, no membership, nothing.

Your goal: read the full contents of `n_globex_1` using only your own
`alice-token`, through a `resources/read` call.

The URI template has three variables: `token`, `orgId`, `noteId`. One of them
is who you are. One of them is what you want. Look at what the third one is
actually used for.

## Constraints

- Token: `alice-token` only.
- `LAB_S8=vuln` must remain set.
- One `resources/read` call is enough.
- No tool call (`tools/call`) is needed or allowed for this challenge.

## Verification

The exploit succeeds when the resource content returned for
`note://alice-token/org_globex/n_globex_1` has `"orgId": "org_globex"`, even
though the call was authenticated as Alice (org Acme).
