# Challenge S11 — The Quota the Gateway Trusts

**Difficulty:** Intermediate
**Class:** CWE-639 / CWE-290 — X-Forwarded-For quota/rate-limit bypass (transport surface)
**Tool under test:** `note_create_limited`

## Setup

S11 lives on the **HTTP transport** — it is the quota/rate-limit sibling of S10 and does not manifest over stdio, because stdio has no request headers. Run the HTTP server instead of `src/server.js`:

```bash
npm install

# Only S11 is left vulnerable; the rest default to "vuln" when unset.
LAB_S11=vuln LAB_S1=fixed LAB_S2=fixed LAB_S3=fixed LAB_S4=fixed LAB_S5=fixed LAB_S6=fixed LAB_S7=fixed LAB_S8=fixed LAB_S9=fixed LAB_S10=fixed node src/http-server.js
# → [mcp-objauthz-lab:http] up on :3010  S11=vuln
```

## Your mission

You are **Alice** (`alice-token`, org *Acme*). The server enforces a per-client creation quota: maximum 3 notes per client. The tool `note_create_limited` tracks this quota.

You have already created 3 notes (the quota is exhausted). You are not an admin, you have no special privileges — only `alice-token`. But you speak to the server directly over HTTP, so **you** decide what headers the request carries.

Connect an MCP client to `http://127.0.0.1:3010/mcp` and call `note_create_limited` with `{ "token": "alice-token", "title": "note 4" }`. It will be rejected (quota exceeded). Then send it again with one extra HTTP header and create a 4th note.

## What to look for

- Which value does the tool use to decide *which client's quota* to check — something the server derived from your token, or something you sent?
- Over stdio there are no headers, so the same tool falls back to the session. Why does moving to HTTP open the hole?
- The exploit is a single request header. No token theft, no membership, no guessing note ids.

## Success criterion

The exploit succeeds when a request you authenticate as **Alice** creates a 4th note despite the 3-note quota, by spoofing the `X-Forwarded-For` header to a new value each time.

## Verify the fix

Restart with `LAB_S11=fixed node src/http-server.js` and repeat: the same spoofed header is now ignored, the quota is keyed to your session, and the 4th note is rejected.
